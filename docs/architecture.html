One chat question, end to end

  1. Edge. API key and bearer token are checked, the caller's request is counted against its rate limit, and the question is scored by the injection guard.
  2. History. The agent loads this identity's conversation from shared state, so any worker can serve the turn.
  3. Retrieve. Identifiers in the question are looked up exactly; dense and lexical candidates are fused; at most two chunks per technique reach the context.
  4. Abstain or answer. If the best match is below the calibrated threshold the API says so without calling the model.
  5. Tools. Tool and feed output is wrapped as untrusted data before the model reads it.
  6. Stream. Tokens pass through the stream sanitiser (credential formats redacted, indicators left intact) and the cited sources are sent as their own events.
  7. Record. Latency, tokens and guard decisions land in /api/v1/metrics; the turn is saved back to shared state.

One investigation, end to end

Verified live on 2026-11-13 with CVE-2021-44228 on gemini-3.5-flash-lite.

  1. Validate IOC. Per-type pattern or ipaddress, normalised (CVE upper, domain lower).
  2. Researcher runs a ReAct sub-agent capped at 10 tool calls, plus a direct retrieval so every report has citations.
  3. Critic returns APPROVED or a gap list; it can send work back once.
  4. Reporter streams the report as report_chunk events.
  5. Check. Technique IDs are validated against the ingested ATT&CK corpus; mismatches are annotated.
  6. Persist. The report is embedded and saved; pgvector finds similar past reports.
  7. Export. GET /investigate/reports/{id}/stix returns a STIX 2.1 bundle.
